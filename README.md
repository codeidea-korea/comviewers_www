# ComViewers 사용자 서비스 프론트

## 2026-10-21 점검 화면을 유지하는 배포 검증

[배포 스크립트](deploy/deploy-www.sh)의 사용자 웹 루트 검증을 보완했다. `/`가200이면 기존처럼 새 index.html의 SHA-256과 비교한다.503일 때는 `/etc/comviewers/main-maintenance.enabled` 파일 존재와 응답 본문의 SHA-256이 `/var/lib/comviewers-main-maintenance/index.html`과 일치하는지 먼저 확인한 뒤, `/?preview=main`의200/새 index.html SHA-256을 검증한다. 서버 loopback의 `--resolve`와 외부 DNS 경로 모두 같은 조건을 적용한다. 임의503·미리보기 실패·HTML/JS/CSS 불일치·인증서 오류는 계속 실패하며 관리자 웹/API 검증과 점검 표식·Nginx 설정은 변경하지 않는다.

배포 주소는 [개발·운영 전용 진입점](../comviewers-api/README.md#2026-10-21-개발운영-배포-진입점-분리)이 고정한다. 개발은 `deploy-dev.sh`, 현재 운영은 `deploy-prod.sh`를 각 서버의 API deploy 폴더에서 실행하며 별도 export는 필요 없다. 사용자 웹 스크립트의 미지정 개발 주소 기본값도 제거했다. 기존 후보 기록 형식은 유지한다. L3 소스/L0 기록이며 diff·분기·주소 전달·Nginx 표식/본문/미리보기 경로를 정적으로 확인했다. 테스트파일·테스트/컴파일/빌드/lint/typecheck·서버 적용/재배포·DB·커밋/push는 수행하지 않았다. 서버에서 사용하려면 수정된 스크립트를 별도로 반영해야 한다.

## 2026-10-21 배포 빌드 경과 시간 출력

[배포 스크립트](deploy/deploy-www.sh)에 의존성 설치/웹 빌드 시작·10초 간격 경과·완료와 실패 종료 코드/로그 경로/마지막 60줄을 추가했다. [공통 동작·개발서버 반영·미검증 경계](../comviewers-api/README.md#2026-10-21-배포-빌드-경과-시간과-실패-로그)를 따른다. L3 스크립트 반영/L0 기록이며 정적 리뷰·서버 파일 해시 대조만 수행했고 웹 빌드·실제 앱 배포는 실행하지 않았다.

## 2026-10-21 개발 인증 보정 적용과 강제 변경

사용자 승인으로 개발 이관3,733계정의 인증 DB 보정을 적용했다. 현재 공개 웹 assets의 강제 변경 처리기와 서버 검증기/출처 mapper를 확인했으며 웹 배포파일은 변경하지 않았다. [적용·독립 재조회·현재 SQL](../docs/handoff/legacy-document-migration-2026-10-20.md#2026-10-21-개발-인증-db-보정-적용과-강제-변경-연결)을 따른다. 지정 계정도 구 비밀번호 인증 후 변경필수 조건을 충족한다. 실제 고객 비밀번호 입력/팝업 실검수·테스트/빌드·배포는 하지 않았다. 아래 문구 복원은 소스 변경이며 DB 보정 미적용 설명은 당시 이력이다.

## 2026-10-21 로그인 입력 안내 문구 복원

이관 인증 보완 중 임의로 교체했던 일반 로그인 아이디·비밀번호 helperText를 기존 `3~20자의 영문, 숫자, 밑줄(_)만 사용할 수 있습니다.` 및 `8~16자의 영문, 숫자, 특수문자(!, @, #, $, %, )만 사용할 수 있습니다.`로 복원했다. 이관 자격 증명을 서버로 전달하기 위한 ID50자·현재 비밀번호100자 입력 한도와 강제 변경 흐름은 유지한다. L0 문구 diff/인접 문맥만 확인했고 테스트·빌드·배포는 하지 않았다. 실제 서버에는 구 비밀번호 검증 코드가 있지만 지정 계정 DB는 아직 v2/BCrypt·변경필수·변경시각 없음 상태임을 읽기 전용 조회로 확인했다. 인증 DB 보정 적용은 여전히 별도 승인 범위다.

## 2026-10-21 이관 고객·담당자 비밀번호 강제 변경 준비

이관 고객의 기존 비밀번호 인증 뒤 기존 강제 변경 팝업으로 진입한다. 일반 로그인은 API와 같은 ID50자·현재 비밀번호100자를 받으며 새 비밀번호8~16자 정책은 유지한다. 담당자 전용 로그인에서는 USER·변경필수·토큰 없음 응답만 제한적으로 받아 원래 비밀번호를 pending 메모리에 유지한다. 변경 완료 후 개인 USER 세션을 담당자로 취급하지 않고 로그아웃한 뒤 같은 조직에서 새 비밀번호 재로그인을 안내한다. 정상 담당자의 C_MANAGER 역할·조직 검사는 유지하며 공통 팝업 안내만 일반화했다. 기존 가입약관 관련 수정은 보존한다.

[API·SQL·정책·미적용 상태](../docs/handoff/legacy-document-migration-2026-10-20.md#2026-10-21-이관-고객의-기존-비밀번호-인증과-강제-변경-준비)를 따른다. L3 소스·L0 문서 정적 확인만 수행했고 DB·테스트파일·테스트/typecheck/lint/빌드·브라우저 로그인·서비스/배포·Git 작업은 없다.

## 2026-10-21 본문 없는 광고성 이메일 수신동의

가입 약관 목록에서 광고 동의행을 분리하고 별도 선택 체크를 기본 미체크로 표시한다. 본문·상세 보기를 만들지 않으며 전체 동의에는 포함하지만 개별 미동의로 다음 단계나 가입을 막지 않는다. 일반·소셜 가입 모두 `marketingEmailAgreed`를 별도로 전달하고 이메일 인증 중 가입 snapshot에 유지한다. 구 API가 반환한 광고 동의 버전만 호환 agreement로 함께 보내 단계적 반영을 지원한다.

[API·DB·최신 SQL과 확인 범위](../docs/handoff/legacy-document-migration-2026-10-20.md#2026-10-21-광고성-이메일-수신동의-본문-제거와-선택-체크-분리)를 따른다. L3 변경의 상태/호출/요청 계약·독립 정적 리뷰만 수행했고 테스트·빌드·타입체크·브라우저·배포는 실행하지 않았다. 기존 게시글 nullable 응답 변경은 보존했다.

## 2026-10-21 이관 게시글의 미수정 날짜 허용

고객센터 공지를 `notice`에서 `support`로 통합한 뒤 공개 API가29건을 반환하지만 고객 화면은 오류를 표시하는 추가 원인을 확인했다. 이관 글은 DB의 nullable `posts.updated_at`과 API 계약에 따라 `updatedAt:null`을 반환한다. `src/api/community.ts`의 게시글 응답 스키마만 `time.nullable()`로 맞춰 목록/상세가 미수정 날짜를 허용하도록 보완했다. 작성일시는 필수이고 실제 날짜 형식 검사는 유지한다. 댓글 스키마와 이관 원본 날짜는 변경하지 않는다. 관리자 게시글 응답은 이미 같은 nullable 계약을 사용한다.

L2/L0 diff·API/DB nullable 계약·목록/상세 공유·소비 경로를 정적으로 확인했다. 수정 전 실제 API/브라우저 오류를 확인했으며 테스트 파일·테스트/빌드/lint/typecheck·수정 후 브라우저·배포·커밋/push는 실행하지 않았다. **현재 배포 화면의 표시에는 이 고객 웹 수정 반영이 추가로 필요하다.** DB/SQL 통합은 [적용 기록](../docs/handoff/legacy-document-migration-2026-10-20.md#2026-10-21-고객센터-notice를-support로-통합)을 따른다.

## 2026-10-21 공통 오류 안내 자동번역 제외

공개 커뮤니티 일본어 선택 직후 `投稿を読み込めませんでした。`로 표시된 오류 문구가 Google 번역 완료 후 `게시물을 로드할 수 없습니다.`로 덮어써지는 현상을 수정 전 브라우저에서 확인했다. [공통 ErrorState](src/components/common/AsyncContentState.tsx)의 오류 영역에 `notranslate`와 `translate="no"`를 추가해 오류 문구와 재시도 버튼의 기존 수동 번역을 유지한다. 게시글·렌탈 후기 목록에 함께 적용되며 번역 사전·재시도 동작·레이아웃은 유지한다.

L2/L0 diff·호출 범위·번역 경계·문서 참조를 정적으로 확인했다. 테스트 파일·테스트/빌드/lint/typecheck·수정 후 브라우저·배포·커밋/push는 수행하지 않았다.

## 2026-10-21 약관 개정이력 드롭다운

서비스 이용약관(`/terms`의 서비스·렌탈·취소/환불 탭)과 개인정보처리방침(`/privacy`)의 공통 개정본 선택을 Figma `MlM5yHJYk6qwwHsi9Icl84`, 서비스 이용약관 `1099:25155` 기준 본문 아래 왼쪽·180×50px·18px/500·밑줄/기존 화살표로 변경했다. 별도 `문서 버전` 문구를 없애고 적용일을 `2026년 8월 31일` 형식으로 표시하며 같은 날짜 개정은 버전 문자열을 덧붙여 구분한다.

약관 페이지는 공개 API에 `includeHistory=true`를 요청하고, `version` URL 파라미터의 문서 ID로 이전 개정본 본문을 표시한다. 종류/이력 여부별 캐시를 분리했고 상품 환불 규정 등의 기본 조회는 현행본을 유지한다. 과거 이력 반환을 위해 API도 함께 반영해야 한다. [API 계약과 공개 조건](../comviewers-api/README.md#2026-10-21-공개-약관-개정이력-조회)을 따른다. L2/L0 diff·호출/응답·선택/캐시·CSS/자산 참조와 독립 정적 리뷰만 수행했다. 테스트 파일·테스트/빌드/lint/typecheck·수정 후 브라우저 렌더링·DB·재기동·배포·커밋/push는 수행하지 않았다.

## 2026-10-20 로그인 출석 포인트 토스트와 내역

인증 API의 `attendancePoints=10`을 받은 USER 세션이 정상 확립되면 `AuthProvider`에서 공통 Toast로 `출석 포인트 10P가 지급되었습니다.`를 표시한다. 일반 로그인·필수 비밀번호 변경 완료·소셜 callback의 초기 세션 복원을 지원하고, 응답 사용자 ID와 session revision을 확인해 오래된 응답을 표시하지 않는다. 화면 이동에도 AuthProvider가 유지되어 토스트가 사라지지 않으며 배경 refresh·담당자 로그인은 알림을 호출하지 않는다. 구버전 API의 필드 누락은 0으로 처리한다.

마이페이지 혜택관리 포인트는 `attendance` 사유를 `출석 포인트`로 표시하고 기존 무료·적립·+10P·5년 후 만료일시 조회를 재사용한다. 토스트/사유의 기존 5개 언어 번역도 연결했다. [지급 정책·서버 구현·미검증 경계](../docs/decisions/0036-point-types-and-coupon-operational-status.md#2026-10-20-로그인-출석-포인트)를 따른다. L2/L0 diff·API schema/세션/토스트·번역 참조 정적 확인이며 테스트 파일·테스트/빌드/lint/typecheck·브라우저·DB·배포·커밋/push는 실행하지 않았다.

## 2026-10-20 운영 배포 origin과 승인 commit 입력

배포 스크립트는 `COMVIEWERS_DEPLOY_PUBLIC_URL`(미지정 시 기존 개발 origin), `COMVIEWERS_USER_DEPLOY_COMMIT`(선택 승인40자리SHA)을 받아 해당 origin의 자산을 검증한다. 준비/활성화 사이 origin·승인 SHA가 다르면 중단한다. 운영 진입점과 최초 설치는 [운영 키트](../comviewers-api/deploy/production/README.md)를 따른다. 선택 이름 번역의 build 입력은 `COMVIEWERS_NAME_TRANSLATION_FRAME_URL`이며 미설정 시 원문 fallback을 사용한다. 같은 등록도메인의 형제 호스트는 기존 격리 정책에서 거부된다. L3 준비/L2 배포 입력/L0 기록으로 diff·참조만 확인했고 실제 서버·npm 설치·테스트/빌드·배포·commit/push는 없다.

## 2026-10-20 첨부파일 백신 의존성 제거 안내 반영

프로필 이미지·가입 이미지·서버실 증빙·커뮤니티 첨부 오류 안내를 파일 형식/크기 검증과 저장 실패·재시도 기준으로 맞췄다. 백신 서비스 준비를 요구하는 안내를 정리하고 API 오류 원문과 6개 언어 번역을 연결했다. 기존 파일 검증·요청 제어·권한·화면 동작은 유지한다. [현재 첨부 정책](../docs/handoff/comviewers-production-server-setup.md#2026-10-20-첨부파일-백신-의존성-제거)을 따른다. L2/L0 정적 diff·번역 연결 확인이며 테스트 파일·테스트/컴파일/빌드/lint/typecheck·브라우저·서버/DB·배포는 미수행이다.

## 2026-10-19 PC 사양 팝업 간격·색상 보정

PC 사양 보기 팝업의 Core 추가 후 밀린 순서 기반 CSS를 제거하고 모든 행에 공통 높이·6px 간격·라벨/값 중앙 정렬을 적용했다. 모바일 override도 맞췄으며 RAM 파랑·DISK 회색·GPU 빨강은 행별 클래스로 복원했다. 다른 화면/팝업과 값·닫기 동작은 유지한다. [변경 범위·확인 한계](../docs/handoff/comviewers-shopping-wireframe.md#2026-10-19-pc-사양-보기-팝업-행-간격과-색상-보정)를 따른다. L2/L0 정적 diff·CSS cascade/치수 검토이며 테스트/빌드·실제 브라우저·배포는 미수행이다.

## 2026-10-16 명시적 주문서 작성 취소와 문의 동선

커밋 전 정적 재검토에서 일반·연장 결제창 종료 후 같은 결제의 승인 완료를 확인한 경로도 복구 기록을 폐기하도록 보완했다. 연장 주문 상세로 바로 이동한 뒤 같은 조건으로 재진입할 때 이전 승인 주문의 취소 화면에 갇히는 경로를 막으며 pending·불명 응답의 원래 생성키 보존은 유지한다. 테스트·실제 결제 실행은 하지 않았다.

일반·연장·보관함 공통 주문서에 `주문서 작성 취소`를 연결했다. 주문 생성 전에는 구매 목록을 유지하고 검증된 내부 진입 URL로 복귀한다. 생성 요청 이후에는 최초 생성 키와 원래 생성 payload를 `POST /api/v1/orders/checkout-cancellation`에 보내 해당 checkout만 취소한다. 불변 `creationKey`와 교체 가능한 결제 준비 `idempotencyKey`를 분리했으며, 생성 응답 유실·준비 실패에서도 취소 복구를 위해 주문 생성 POST를 재호출하지 않는다. 일반 생성은 기존 `order:{UUID}` 전송을 유지하고 취소 API에는 UUID를 전달한다. 장바구니·상품상세·렌탈/파트 보관함·연장 진입에서 목록 조건과 hash를 보존하며 `checkoutReturnTo`가 허용한 내부 구매 화면만 복귀 대상으로 사용한다.

완료·부분 복구 결과는 항목별 사유를 모달에서 확인한 뒤 복귀한다. 부분 복구를 전체 성공으로 표시하지 않으며 처리 중·차단·응답 불명은 화면에 머물러 같은 원래 키로 다시 확인한다. 취소를 시작한 주문은 결제 제출을 잠가 취소와 재결제를 구분한다. PG 창 닫기 후 서버 `retryable`인 같은 주문의 결제수단·현금영수증 재선택은 유지하고, 종료 응답에서도 생성 키를 버리지 않는다. 상품·장바구니·보관함·연장제안·혜택 조회를 무효화하며 포인트 입력 초기화 X 버튼을 추가했다. 새로고침으로 최초 키가 유실되지 않도록 조직·행위 회원·구매 선택별 `sessionStorage`에 생성 키·원래 생성 요청·안전한 복귀 URL만 최대 2시간 보관한다. 원 요청의 연락처는 요청 지문 재검증에 필요한 제한적 임시 보관이며 결제 준비 입력·영수증 식별번호·PG 키·견적 스냅샷은 저장하지 않는다. 저장 실패 시 주문 생성 POST를 시작하지 않는다. 같은 checkout 재진입에서는 새 주문을 만들지 않고 원 키의 취소 결과를 확인하며, 취소 결과 확인 후 복귀·승인/가상계좌 발급 확인·로그아웃 시 폐기한다.

문의 목록은 유형 텍스트와 행 전체 overlay를 제거하고 `보기` 열/버튼에서 기존 문의 대화를 연다. 모바일 카드도 `보기` 버튼을 사용한다. RCPC 공통 행·모바일·즐겨찾기의 개별 빠른 실행 문의는 `productNo` 검색 목록으로 이동하며 신규 접수 자동 열기는 `compose=1` 또는 기존 `pcAssetIds` 진입으로 분리했다. 일괄 문의는 기존 `InquiryAction`을 유지한다.

L2/L3/L0 소스·계약·기록 변경으로 diff·호출·키 보존·nullable 응답·URL 허용 목록·표 이벤트·캐시 키를 정적으로 확인했다. [ADR 0010](../docs/decisions/0010-wireframe-commerce-workflow-persistence.md)의 최신 명시적 취소 정책과 신규 migration/API를 함께 반영해야 한다. 테스트 파일·테스트·컴파일·빌드·lint·typecheck·서비스/브라우저/PG 실행·DB 적용·배포는 하지 않았다. Figma 피드백 원본 image16(node 2836:168671)의 결제 버튼 바로 아래 동일 너비 행, 포인트 입력 오른쪽/전액사용 왼쪽 X, 문의 목록 맨 오른쪽 보기 컬럼 위치를 대조했다. 기존 공용 버튼·모달·아이콘을 재사용했으며 실제 화면 실측·시각 일치 검수는 미실행이다.

## 2026-10-15 마이페이지 이름만 무료 위젯으로 격리 번역

쿠폰명과 서버실명 표시를 `LocalizedServiceName`/`useLocalizedServiceName`에 연결했다. 쿠폰 보유·사용·다운로드, RCPC 홈/목록/즐겨찾기/선택·사양·연장, 문의 상품, 주문·환불·보관함의 서버실명이 대상이다. 원본 DTO, 품번·별칭·지역·주문번호, 검색/정렬/선택 value, API 요청, 글자 크기·CSS·기존 DOM 구조는 유지한다. 기존 번역표에 있는 이름은 직접 번역하고, 미등록 한국어 이름은 영어·일본어·간체·번체에서 무료 위젯에 요청한다. 한국어·베트남어·빈 값·민감정보 형태/길이 제한에 걸린 이름은 기존 표시를 유지한다.

마이페이지 문서에는 Google 스크립트를 추가하지 않는다. `service-name-client.ts`가 별도 사이트의 sandbox iframe에 무작위 요청 ID·언어·이름 문자열만 전달한다. 회원/쿠폰/서버실 ID·인증정보·페이지 URL·본문은 메시지에 넣지 않는다. 출처·창·요청 ID·응답 형태를 검증하며, 이름 목록이 바뀌면 새 문서/배치로 번역한다. 30초 제한·최대1회 재시도·원문 fallback을 적용하고, 세션 범위/언어 변경과 구독 해제 시 이전 요청을 폐기한다. 캐시는 최대200개·5분의 메모리만 사용하며 마지막 구독 해제 시 삭제한다. 이메일/전화번호/URL/토큰/비공개 표식 등의 차단은 보조 장치이며 사람 이름 등 모든 민감정보를 자동 판정하는 기능은 아니다. 이름 자체가 Google에 전달되는 범위다.

개발은 `npm run dev`의 `127.0.0.1/localhost:5301` Vite가 실제로 열릴 때 이름 번역 서버도 자동 시작한다. 앱 `http://127.0.0.1:5301` 또는 `http://localhost:5301`에서 번역 화면 기본값은 `http://127.0.0.2:5317/frame.html`이다. 별도 도구로 앱을 실행할 때만 `npm run names:dev`를 독립 실행한다. Vite 종료 시 자신이 시작한 이름 서버만 닫고, 기존 포트 점유 프로세스는 보존하고 경고한다. 빌드·preview·다른 포트에서는 자동 시작하지 않는다. 이름 전용 서버는 다른 loopback 호스트에 정적 파일3개만 제공하며 `/api/` 프록시·계정·DB 연결이 없다. 부모 주소 변경 시 `NAME_TRANSLATION_PARENT_ORIGINS`를 정확한 origin의 쉼표 목록으로 설정한다. 호스트/포트는 `NAME_TRANSLATION_HOST`/`NAME_TRANSLATION_PORT`로 설정하고 프론트 `VITE_NAME_TRANSLATION_FRAME_URL`도 맞춘다. 같은 호스트의 다른 포트는 쿠키 격리가 아니므로 거부한다.

운영은 인증 쿠키를 공유하지 않는 별도 HTTPS 사이트가 필요하다. `name-translation/frame.html`, `frame.js`, `frame.css`만 별도 정적 호스트에 배치하고 HTML의 `__PARENT_ORIGINS__`를 허용할 앱 origin 목록으로 대체한다. `serve.mjs`를 HTTPS 프록시 뒤에 사용할 경우 meta 주입은 자동이며 프록시는 Host를 loopback upstream 주소로 설정해야 한다. 배포 호스트에도 `serve.mjs`의 CSP/frame-ancestors·no-referrer·no-store·nosniff·Permissions-Policy를 동일하게 적용하고 서비스 인증 쿠키/API를 제공하지 않는다. 프론트 `VITE_NAME_TRANSLATION_FRAME_URL=https://별도사이트/frame.html`를 지정한다. 부모와 같은 origin·같은 호스트·같은 마지막 두 도메인 라벨의 형제 호스트는 거부하며, 다단계 공용 접미사도 보수적으로 거부할 수 있다. 운영 주소가 없거나 격리 조건에 맞지 않으면 원문을 유지한다. 이름 전용 위젯 가용성/공급자 적용 조건·운영 호스트 보안은 배포 전 확인 대상이다.

[Vite 설정](vite.config.ts)은 `/api/`를 `http://127.0.0.1:8080`으로 전달하며 원래 Host와 전달된 HTTPS 헤더를 보존한다. 로컬 `.env.local`의 `VITE_API_BASE_URL=/`로 브라우저의 API 호출을 현재 출처로 통일했다. [환경 예시](.env.example)도 같은 기준이다. Cloudflare 터널은 고객 웹 5301에 연결하고 개발 서버와 API 8080을 함께 실행한다. 설정 반영 후 기존 공유 주소에서 새로고침하며, 반영되지 않으면 고객 웹 개발 서버를 재시작한다.

허용 호스트는 현재 발급된 터널 하나이며 주소가 바뀌면 `server.allowedHosts`를 갱신한다. 백엔드 CORS·인증·쿠키 설정은 변경하지 않았다. 소셜 로그인·결제·이메일의 외부 콜백/리다이렉트 URL은 이 프록시만으로 공유 주소로 바뀌지 않는다. L3/L0 정적 diff·API 경로·Host/전달 헤더·쿠키 범위 리뷰이며 테스트·컴파일·빌드·lint·typecheck·실제 HTTP/로그인·배포 검증은 미실행이다.

## 2026-10-15 번역 줄바꿈과 반응형 보완

사용자 요청으로 글자 크기를 유지하고 공통 푸터·상품 즉시 사용 필터·로그인 체크박스·회사소개 제목/설명과 메인 소개/보안 카드의 줄바꿈·높이 확장을 보완했다. 푸터는 회사정보·상담 영역을 가용 폭에 맞춰 배치하고, 회사소개는 고정 높이로 긴 설명이 잘리지 않도록 한다. 메인 일본어 소개 카드의 grid 최소 폭 확장도 수정했다. 기존 모바일 카드 가로스크롤과 브레이크포인트를 유지하며 RCPC 제목은 자동번역에서 보호한다. 이전 가입 약관 번역 관련 동시 변경은 보존했다.

로컬 5301에서 영어·일본어·간체·번체의 상품 목록/회사소개/로그인을 1440·390·320px로 확인했고 각 화면의 가로 넘침 후보 0건을 관측했다. 회사소개 간체는 1024·768px도 확인했다. 결과와 한계는 [브라우저 기록](../tmp/translation-wrap-20261015/results.json)을 따른다. L2 승인 실화면 확인/L0 기록이며 font/font-size 선언 동일·diff와 CSS 인접 문맥·독립 리뷰를 확인했다. 테스트 파일·테스트 명령·컴파일·빌드·lint·typecheck·배포는 수행하지 않았다. 로그인 이후 화면·상품이 담긴 장바구니·가입 2단계의 실행 검수는 포함하지 않는다.

## 2026-10-15 RCPC 자동 접속정보 중복 조회와 요청 제한 토스트 보완

[WAN IP 표시](src/routes/mypage/-components/RcpcDeviceActions.tsx)는 [가시성 판단](src/routes/mypage/-components/rcpc/useVisibleConnection.ts)으로 실제 보이는 영역에서만 자동 조회한다. CSS로 숨긴 PC/모바일 사본과 화면 밖 행은 조회하지 않고, 성공한 같은 컴포넌트는 스크롤 재진입만으로 다시 조회하지 않는다. [RCPC API](src/api/myRcpc.ts)는 같은 서비스·장비·조회 종류의 진행 중 WAN/ID 요청을 [공유](src/api/inFlightRead.ts)하고 완료 즉시 제거한다. 소비자별 취소를 분리하며 결과·비밀번호를 Query 캐시/저장소에 추가하지 않는다. 복사 감사·비밀번호 공개 요청은 합치지 않는다.

자동 WAN 조회 오류는 해당 칸의 기존 `조회 실패` 표시로 남기고 토스트를 띄우지 않는다. 429는 `Retry-After` 이후 최대 한 번 재시도하며, 자동 대기 상한 10분을 넘는 응답은 조기에 재시도하지 않는다. 숨김/해제 시 예약·소비자를 정리하고 직접 복사 오류의 기존 안내는 유지한다. [API 변경](../comviewers-api/README.md#2026-10-15-rcpc-목록-표시용-요청-제한-분리)과 함께 반영해야 한다. L2/L3/L0 정적 diff·인가 범위·공유/취소·가시성·429 분기·참조/독립 리뷰이며 테스트 파일·테스트·컴파일·빌드·lint·typecheck·실제 브라우저·배포는 미실행이다.

## 2026-10-15 복사 붙여넣기 본문 서식 정리

공통 에디터에 관리자 웹과 동일한 [본문 정규화](src/components/ui/richTextEditorFormatting.ts)를 연결했다. Word·웹 등에서 복사한 텍스트·문단·목록·줄바꿈과 지원하는 글자/문단 서식을 유지하고, 미지원 속성·Office 메타데이터·외부 이미지 URL은 제외한다. 글꼴/크기/줄간격·제목은 기존 허용 범위로 맞추며 미지원 표/레이아웃은 내용 순서대로 블록화한다. 기존 첨부 ID·업로드/미리보기·서버 검증·본문 크기/깊이 제한은 유지한다.

붙여넣기·초기 값·HTML/JSON 콜백·controlled 동기화 비교에 같은 정리 기준을 적용한다. 줄바꿈 등 비텍스트 노드의 marks를 제거하고 JSON 노드/속성/서식을 API 허용 목록으로 새로 구성한다. 블록/링크의 글자 서식도 내부 span/mark로 옮기고 내부 복사의 공백/목록 문맥은 검증한 slice 정보만 남긴다. [관리자 웹 기록](../comviewers-admin-www/README.md#2026-10-15-복사-붙여넣기-본문-서식-정리)을 따른다. L2/L0 정적 diff·API 계약·import/타입·양 웹 helper 일치·독립 리뷰 범위다. 테스트 파일·테스트·컴파일·빌드·lint·typecheck·실제 Word 붙여넣기/저장·배포는 미실행이다.

## 2026-10-15 마이페이지 목록 갱신 깜박임 완화

RCPC·즐겨찾기·문의와 주문·포인트·쿠폰 목록에서 새 검색 조건·정렬·페이지를 조회하는 동안 같은 범위의 직전 성공 응답을 유지한다. [공통 계정 조회](src/routes/mypage/-components/shared/AccountReadCommon.tsx)는 목록 호출에만 opt-in하며 repository 인스턴스·목록 prefix·키 길이를 대조한다. 주문 상세·프로필·구매확정 후보에는 적용하지 않고, 보유/사용 쿠폰은 같은 탭에서만 유지한다. 주문은 이전 응답의 렌탈 상태 필터도 유지해 새 조건으로 이전 행을 다시 걸러 본문이 사라지는 것을 방지한다. 포인트 잔액과 목록 개수도 새 응답 전까지 직전 표시를 유지한다.

기존 DOM·CSS·열·검색 적용 방식과 권한 거부 시 데이터 숨김을 유지한다. 직전 행은 갱신 중 `inert`로 조작을 막고 정렬·검색·페이지 이동은 계속 허용한다. 페이지 표시는 요청한 번호를 사용한다. RCPC의 query 기반 key와 선택/팝업 초기화는 유지하며, 주문 작업 팝업은 조건 변경 시 초기화해 이전 대상으로 실행되지 않게 한다. 조회 실패 후에는 새 정상 응답 전까지 이전 데이터 보존을 중단한다. 정상 백그라운드 갱신의 동작과 번역 활성화 시 전체 문서 이동은 이번 범위에서 변경하지 않았다.

L2/L0 정적 diff·query 범위/호출·선택/팝업·페이지·DOM/CSS 참조만 확인했다. 테스트 파일·테스트·컴파일·빌드·lint·typecheck·실제 브라우저 검수·배포는 수행하지 않았다. 실제 네트워크 지연 중 전환·403·빠른 연속 페이지 이동의 실행 검수는 남아 있다.

## 2026-10-15 화면 로딩 실패 복구 보완

후속 사용자 명시 요청으로 실제 API에 연결한 로컬 production 빌드·브라우저 검수를 수행했다. 초기 빌드 15.04초, 동시 작업과 분리한 전용 출력 빌드 7.79초에 성공했다. 상품/분류·상세·기간 조작·필터·정렬/검색·페이지 변경·뒤로가기·문의 선택 팝업·RCPC/즐겨찾기/주문/보관함/혜택/담당자/본인확인·장바구니의 16개 검수 묶음에서 오류 페이지·콘솔 오류를 재현하지 못했다. 후속 변경된 마이페이지 3화면도 재검수했고 전용 빌드 이후 소스 변경 0건을 확인했다. 실제 helper/경계 연결 격리 화면의 일시 실패 2회 시도 성공·지속 실패 2회 제한·실패 후 재진입·렌더 오류 후 화면 이동·query 변경 시 입력/상태 유지 5개도 통과했다. [구조화된 결과](../tmp/route-recovery-live-20261015/result.json), [격리 상태 보존 화면](../tmp/route-recovery-live-20261015/user-recovery-state.jpg)을 따른다. 격리 검수는 loader Promise 실패를 모사하며 실제 HTTP 모듈 실패 캐시 복구를 증명하지 않는다. 변경 전 화면과의 전체 픽셀 비교는 미실행이며 오류 경계 마크업·문구·스타일은 정적 동일성을 확인했다. 구매 버튼 클릭은 주문/결제 가능성으로 자동 승인 검토에서 차단되어 실행하지 않았으며 실제 저장·결제·환불·DB 변경·배포는 없다. 아래 최초 정적 검토의 미빌드/미브라우저 상태는 이 후속 실행 범위에서 대체한다.

[화면 모듈 로더](src/app/lazyRoute.tsx)는 기존 분할 로딩을 유지하며 import 로딩 오류에만 350ms 후 1회 재시도한다. 최종 실패한 lazy 인스턴스는 [오류 경계](src/app/RouteErrorBoundary.tsx)의 후속 화면 이동·기존 재시도에서 초기화하며 성공한 화면 인스턴스는 유지한다. [라우터](src/AppView.tsx)는 실제 표시하는 deferred location의 key를 경계에 전달해 주소 이동과 화면 전환의 시점 차이로 이전 오류에 고착되는 경로를 보완했다. 새 화면에서 막 발생한 오류는 경로 변경만으로 중복 자동 재시도하지 않는다.

기존 오류 문구·버튼·DOM/CSS와 업무 요청 처리는 유지하며 자동 전체 새로고침·API mutation 재시도는 추가하지 않았다. 콘솔에는 import/render 구분과 컴포넌트 스택을 남기며 별도 오류 원문·요청 URL·업무 데이터를 수집하지 않는다. 브라우저의 모듈 실패 캐시나 삭제된 배포 파일은 같은 URL 재시도만으로 복구가 보장되지 않으며, 보고된 모든 발생 원인을 확정한 것은 아니다. ## 2026-10-15 뒤로가기 스크롤 위치 복원

## 2026-10-14 상세 필터 여백과 금액 변경 갱신

## 2026-10-13 동일 사업자 일괄문의 제한

이용 RCPC·즐겨찾기·주문내역에서 선택한 대상의 운영 사업자가 같을 때만 일괄문의 작성으로 진입한다. 공통 `InquiryAction`이 클릭 시 고객의 문의 가능 RCPC를 조회하고 `serverRoomBusinessKey`를 비교한다. 다른 사업자가 섞이면 기존 공통 토스트에 `일괄문의는 동일 사업자에서만 가능합니다.`를 표시하며 작성 팝업을 열지 않는다. 서버실이 달라도 사업자가 같으면 허용한다.

문의 작성의 상품 선택·추가·유형 다음 단계·접수 직전에도 동일 기준을 적용한다. 기존 대화의 상품 추가는 조회 가능한 기존 대상과 새 대상을 비교하고, 기존 상품 대상 등 조회 범위 밖의 대상까지 포함한 최종 검증은 API가 수행한다. 주문내역의 클릭 시 대상 snapshot과 접수 후 선택 초기화는 공통 문의 액션에 연결했다. 사업자번호 원문 대신 API의 불투명 비교 키를 사용하며 구형 API에서 키가 없거나 사업자를 확인할 수 없는 복수 대상은 동일 안내로 차단한다. 개별/무대상 일반문의와 별도 해지 신청은 유지한다. [ADR 0020](../docs/decisions/0020-operation-request-chat-participant-authorization.md#2026-10-13-동일-사업자-일괄문의-제한)을 따른다.

L2/L0 정적 diff·응답/schema·공통 진입/작성/추가·문구·참조만 확인했다. 테스트 파일·테스트·컴파일·타입체크·lint·빌드·브라우저·API/DB 실행·배포는 미실행이다. 새 API와 고객 웹을 함께 반영해야 한다.

## 2026-10-13 사용중지 쿠폰 보유 표시

## 2026-10-13 입점 이메일 자동완성 주소 분리

입점 신청 이메일 아이디·도메인에 전체 주소가 채워졌을 때 각각 `@`로 분리하도록 수정했다. 아이디는 controlled input과 `autocomplete=email`로 연결하고 도메인에는 `name=emailDomain`·`autocomplete=off`를 지정했다. 어느 칸에 전체 주소를 자동완성하거나 붙여넣어도 아이디·도메인을 각각 표시하며, 아이디 뒤에 `@`를 직접 입력하면 도메인 칸에서 이어 쓸 수 있다. 기존 도메인 선택·직접 입력은 유지한다.

브라우저가 변경 이벤트 없이 자동완성한 경우도 제출 직전 실제 DOM 값을 읽어 같은 정규화 함수를 적용한다. 검증 결과의 아이디·도메인을 API 입력과 재시도 지문에 함께 사용하며, 양쪽에 서로 다른 전체 주소 또는 여러 `@`가 들어오면 기존 이메일 검증으로 차단한다. 앞선 신청 성공 캐시 초기화와 실패 입력 보존은 유지한다.

L2 소스·L0 문서의 정적 diff·입력 핸들러·DOM/검증/저장 값 대응·참조를 확인했다. 테스트 파일·테스트·컴파일·타입체크·lint·빌드·브라우저 자동완성 재현·배포는 변경/실행하지 않았다.

## 2026-10-13 입점 신청 완료 후 재진입 입력값 초기화

## 2026-10-13 에디터 본문 이미지 저장 속성 정합화

커뮤니티 본문에 이미지를 삽입한 뒤 등록할 때 `본문 서식 정보를 확인해 주세요`가 발생하는 원인은 TipTap 이미지의 기본 `width`·`height` 속성이 저장 JSON에 남아 API 이미지 속성 허용 목록과 충돌하는 것이다. 공통 `persistentEditorDocument`가 이미지 속성을 `attachmentId`·`alt`·`title`만 새 객체로 복사하도록 수정했다. 미리보기 URL·크기 등의 속성은 저장 JSON에서 제외하고, 에디터 원본·이미지 미리보기·비이미지 서식·첨부 ID 연결·서버 검증은 유지한다. 관리자 웹의 같은 직렬화 함수에도 적용했다.

L2 소스·L0 문서의 정적 diff·서버 허용 속성·재귀/호출·문서 참조를 확인했다. 테스트 파일·테스트·타입체크·lint·빌드·브라우저 등록 재현·배포는 변경/실행하지 않았다. 열린 에디터는 새로고침 후 이미지를 다시 삽입해 등록을 재확인해야 한다.

## 2026-10-13 결제창 종료 후 결제수단 재선택

후속 사용자 요청으로 정상 결제창 종료 안내문구를 제거하고 버튼은 기존 `주문하기`를 유지한다. 재결제 동작과 결과 불명 상태 확인은 유지하며 이번 L1/L0 표시 변경은 diff·문구/참조만 정적으로 확인했다. 테스트·빌드·브라우저 검증·배포는 미실행이다.

결제 상태 확인 API의 쿼리를 공통 클라이언트 `query` 옵션으로 전달해 요청 전 주소 검증 오류를 수정했다. 일반 주문과 기간 연장·보관함 공통 주문서는 창 닫기 후 서버가 `retryable`을 확인하면 결제수단 선택을 다시 열고, 상품·혜택·주문자·금액·생성 주문번호는 보존한다. 재결제는 새 결제 멱등키로 기존 주문의 결제 준비만 호출하여 소진된 장바구니/보관함으로 새 주문을 만들지 않는다. 승인 불명·계좌 발급·만료는 재결제를 열지 않으며, 최초 가상계좌 준비의 현금영수증 신청 snapshot을 유지한다.

[ADR 0010](../docs/decisions/0010-wireframe-commerce-workflow-persistence.md#2026-10-13-결제창-닫기-후-같은-주문-재결제)을 따른다. 새 API의 `allowRetry`/`retryable` 계약과 함께 반영해야 한다. L3/L2/L0 정적 diff·쿼리/스키마·주문/키 보존·선택 잠금·호출 참조만 확인했으며 테스트 파일·테스트·타입체크·lint·빌드·브라우저/PG·DB 실행·배포는 미실행이다.

## 2026-10-13 연장대기 실행 중 RCPC 재부팅 허용

후속 사용자 요청으로 로컬 5301의 연장대기 필터·상세 화면을 실제 확인했다. 조회된 2건 모두 재부팅 버튼이 비활성화됐고, 개발 DB 읽기 전용 대조에서 두 계약의 최신 연결 ComBar 장비·heartbeat가 없었다. 상세 버튼의 DOM `isEnabled=false`와 행 캡처를 확인했지만 `연장대기 + ONLINE` 대상이 없어 활성화·확인 팝업은 아직 실화면 미검증이다. 실제 재부팅 요청·DB 변경·빌드·배포는 하지 않았다.

사용자 QA 후속 요청으로 공통 RCPC 재부팅의 `using`·`active` 전용 조건을 제거하고 기존 `rentalServiceAccessible`과 실행 중(`ONLINE`) 조건을 사용한다. 렌탈 중과 연장대기의 KST 만료일 당일·+1일까지 요청을 허용하며, 실제 종료·환불·시작 전·D+2 포맷대기·오프라인은 차단한다. 서버의 재부팅 권한/가능 여부·처리 중 차단·재통신 대기·멱등 요청·확인 팝업은 유지한다. 목록·홈·즐겨찾기가 같은 공통 컨트롤을 사용한다. [현행 이용 유예 정책](../docs/decisions/0032-rental-contract-and-pc-operational-status.md)을 따른다.

L2 소스·L0 문서의 정적 diff·허용 상태/날짜 경계·공통 호출/서버 조건·참조만 확인했다. 테스트 파일·테스트·타입체크·lint·빌드·실제 브라우저/API 재부팅·배포는 변경/실행하지 않았다.

## 2026-10-13 비밀번호 재설정 동일 비밀번호 안내

비밀번호 재설정 API가 `A026`을 반환하면 기존 새 비밀번호 입력 오류 영역에 `기존 비밀번호와 다른 비밀번호를 입력해 주세요.`를 표시한다. 새 비밀번호를 수정하면 오류가 초기화되고 같은 유효 링크로 재시도할 수 있다. 기존 형식 오류 `A006`과 링크 오류 `A017` 처리는 유지한다. [API 기록](../comviewers-api/README.md#2026-10-13-비밀번호-재설정-동일-비밀번호-차단)을 따른다.

L2 화면·L0 문서의 정적 diff·오류 코드/표시/초기화·참조만 확인했다. 테스트 파일·테스트·타입체크·lint·빌드·실제 브라우저·배포는 변경/실행하지 않았다. API와 함께 반영해야 한다.

## 2026-10-13 상품 리스트 상품명 검색 UI 제거

사용자 요청으로 상품 리스트의 상품명 검색 입력창·버튼과 전용 화면 상태·훅 setter·CSS를 제거했다. 기존 상품 필터와 URL/API keyword 조회 계약은 유지한다. L2 소스·L0 문서의 diff·호출/CSS 참조를 정적으로 확인했으며 테스트·타입체크·lint·빌드·브라우저·배포는 미실행이다.

## 2026-10-13 렌탈 상태 6개 통일

고객 RCPC·주문내역의 현재 렌탈상태는 신규등록·신규대기·렌탈 가능·렌탈 중·연장대기·포맷대기 6개/null API 계약을 사용한다. `termination_waiting` 표시명은 포맷대기이며 KST 만료일 D−1~D+1 연장대기, D+2부터 포맷대기를 사용한다. 구형 `format_waiting` 서버상태 분기와 주문의 별도 렌탈 표시값을 현재 schema·필터·표시에서 제거한다. 계약이 없거나 서비스 시작 전인 상태를 임의로 렌탈 중으로 표시하지 않는다. 교체된 원상품·현재 PC·환불/기간 연장·문의 대상 판단은 별도 계약/주문/교체 근거로 유지한다. 연결 상태·과거 계약의 종료/환불과 주문 결제 상태는 운영 상태와 분리한다.

[ADR 0032](../docs/decisions/0032-rental-contract-and-pc-operational-status.md#2026-10-13-현재-상태와-구형-상태-정리)를 따른다. L2 소스·L0 문서의 diff·schema/표시/필터·KST 날짜 경계·호출 참조만 정적으로 확인했다. 테스트 파일·테스트·타입체크·lint·빌드·브라우저·API 실행·배포는 변경/실행하지 않았다. 고객 주문·RCPC의 새 API와 함께 반영해야 한다.

## 2026-10-13 후기 validation 버튼 위치 유지

공통 후기 작성·수정 팝업의 입력창과 버튼 사이 기존 40px 여백을 고정 오류 표시 영역으로 사용한다. 오류가 생겨도 버튼 위치와 카드 높이는 유지하며 긴 오류는 해당 영역 안에서 스크롤한다. 검증 문구·등록 조건·API는 유지한다. L2 UI·L0 문서의 JSX/CSS diff·공통 호출·선택자 참조만 정적으로 확인했다. 테스트·타입체크·lint·빌드·브라우저 실행·배포는 미실행이다.

후속 수정으로 주문내역의 후기 팝업을 닫거나 새로 열 때 저장 mutation을 reset해 이전 validation·저장 오류를 제거한다. 저장 중 닫기 차단과 저장 성공 후 후기 보기 전환은 유지한다. 공유 서버의 열린 팝업에서 빈 입력·별점 초기 상태에 이전 오류가 남는 현상을 읽기 전용으로 확인했고, 변경 자체는 L2 정적 diff·상태/호출 리뷰만 수행했다. 테스트·타입체크·lint·빌드·수정 후 브라우저 실행·배포는 미실행이다.

user1의 품번 80009 등록 실패는 공유 서버 Nginx access/error 로그에서 2026-10-13 15:06:28 KST의 POST가 API upstream `127.0.0.1:18080` 연결 거부로 502 응답한 것으로 확인했다. systemd/API 로그상 15:06:02 중지 시작·15:06:32 중지 시간 초과 후 재기동·15:06:46 Tomcat 기동 완료 사이의 요청이었다. 개발 DB SELECT에서는 활성·이용 시작·구매확정 완료·기존 후기 없음·주문 상품 연결 일치를 확인했다. 이후 공유 서버 외부·upstream 후기 조회 GET은 200이며 API 서비스는 active/running이었다. 실제 후기 등록·DB 변경·서버 재기동은 수행하지 않았다.

## 2026-10-13 보관함 장바구니 전환 제거

보관함 구매 버튼은 신규 렌탈 ID·기간, 파트 제안 ID·수량과 연장 제안/렌탈 ID를 공통 `/checkout` 주문서로 직접 전달한다. 진입 시 장바구니 이동 API를 호출하지 않으며 견적 조회 중 보관함에 유지한다. 서버 직접 상품/연장 견적을 같은 주문서에 표시하고 주문자·할인·결제수단·현금영수증과 기존 PG 창/0원 승인을 공유한다. 실제 주문 생성 이후 동일 요청·멱등키·생성 주문을 유지하는 재시도/결과 확인 흐름을 사용한다. [현행 결정](../docs/decisions/0010-wireframe-commerce-workflow-persistence.md#2026-10-13-보관함-원천-직접-주문)을 따른다.

API 직접 원천 견적/생성 계약과 V188 migration을 함께 반영해야 한다. L2 UI·L3 결제 계약·L0 문서 정적 diff·선택/스키마·서버 견적 합계·호출/재시도·참조만 확인하며 테스트·타입체크·lint·빌드·브라우저/API/PG·배포는 미실행이다.

## 2026-10-13 기간 연장 공통 주문서와 보관함 구매

이용 RCPC의 연장 팝업에서 선택한 기간·대상을 공통 `/checkout` 주문서로 전달한다. 전용 연장 주문서 화면과 라우트, 보관함의 별도 연장 결제 대기 카드를 제거했다. 관리자가 전달한 기존 렌탈 PC는 보관함의 일반 상품 행·체크박스·합계·구매하기를 사용하며, 연장 PC와 신규 렌탈/파트를 함께 선택해 주문 하나·결제 한 건으로 진행한다. 주문자 정보·쿠폰·포인트·결제수단·현금영수증 입력과 PG 창은 기존 주문서 컴포넌트를 공유한다.

연장 견적/생성 API가 보관함 제안과 일반 상품의 선택 ID·서버 재견적·해시를 확인하고, 생성된 주문번호를 공통 결제 준비에 전달한다. 0원은 내부 승인, 금액이 있으면 선택한 결제수단을 사용한다. 생성 응답 불명·결제 준비 재시도는 같은 요청/멱등키/주문을 유지하고 PG 결과 불명에서는 새 주문 생성을 잠근다. API의 새 합산 견적 필드와 함께 반영해야 한다. L3 결제·L2 UI·L0 문서 정적 diff·참조·스키마·금액 대조·호출만 확인했다. 테스트·타입체크·lint·빌드·브라우저/API/PG 실행·배포는 하지 않았다. 새로고침 이후 주문 복구와 취소 후 소진된 일반 장바구니 항목의 재진입은 기존 미결 과제다.

## 2026-10-13 보관함 주문 확인 팝업 제거

기획에 없는 `보관함 상품 주문` 팝업과 장바구니 이동 안내를 제거했다. 보관함의 구매 버튼에서 기존 혼합 상품 전환 API를 호출하고 선택한 상품의 주문서로 바로 이동한다. 요청 중 버튼·선택 잠금과 동일 멱등키 재시도를 유지하며, 연속 클릭은 즉시 잠금으로 중복 호출을 차단한다. [보관함 기획 원문](../docs/requirements/comviewers-pdf-description-inventory.md#trace-u39)을 따른다. L2 기능·L0 문서 정적 diff·호출/재시도 흐름·참조만 확인했으며 테스트·타입체크·lint·빌드·브라우저/API 실행·배포는 미실행이다.

## 2026-10-13 재부팅 실패·만료 안내 제거

마이페이지 RCPC 목록·대시보드의 공통 재부팅 컨트롤에서 기획에 없는 실패/만료·명령 접수/재통신 대기·통신 재개·권한/상태 조회 오류·요청 오류 안내를 모두 제거했다. 확인 팝업의 `요청 중…` 라벨도 기본 `재부팅`으로 복귀하고, 안내 문구 전용 CSS와 모바일 카드 높이 확장 조건을 제거했다. 요청 처리 중 버튼·닫기 비활성화와 조회·중복 요청 방지 로직은 유지한다. API는 현재 렌탈·고객 조직·장비와 일치하는 고객 재부팅 요청만 상태로 반환하며, 장비 전체의 재부팅 중복 생성 방지는 별도 유지한다. [API 기록](../comviewers-api/README.md#2026-10-13-현재-렌탈-재부팅-상태-조회)을 따른다. L2 UI·L0 문서 정적 diff·공통 호출/표시·CSS 참조만 확인했으며 테스트·타입체크·lint·빌드·실제 브라우저/API·재기동·배포는 미실행이다.

## 2026-10-13 쿠폰 최대 할인금액 표시

보유·다운로드 가능 정률 쿠폰의 `maximumDiscountAmount`를 조회해 기존 혜택 문구에 최대 할인금액을 표시한다. 기존 NULL/누락 응답은 종전 문구를 유지한다. 실제 상한은 API의 공통 주문 견적에서 적용하며 V186·API 반영이 필요하다. L2/L0 정적 diff·응답/표시 계약만 확인했고 테스트·타입체크·빌드·브라우저·DB 적용·배포는 미실행이다. [쿠폰 정책](../docs/decisions/0015-figma-pm-policy-baseline.md#상품장바구니주문-가격-모델)을 따른다.

ComViewers 사용자용 웹 애플리케이션이다. 인증, 상품 탐색, 장바구니·주문, 마이페이지, 문의·커뮤니티 화면을 제공한다. 작업 이력과 검증 범위는 [전체 인수인계](../HANDOFF.md), 기능별 정책은 [문서 인덱스](../docs/INDEX.md)에서 확인한다.

입점 신청은 동일 사업자의 추가 신청과 한 번의 복수 서버실 제출을 지원한다. 공통 사업자·담당자·증빙·약관을 입력하고 Figma v1.5의 `+ 서버실 추가`로 서버실명·상담 메신저를 입력한다. 최초 영역은 유지하며 추가 영역만 X로 삭제한다. 입력 순서와 서버실별 값은 제출·재시도에 포함되고 API는 각 서버실을 독립 심사 건으로 저장한다. 이번 복수 신청 변경은 L2/L3 정적 확인 범위이며 실제 화면·API·테스트·빌드·DB 적용·배포는 미검증이다. [입점 정책](../docs/decisions/0015-figma-pm-policy-baseline.md#주문입점-동의와-시점-스냅샷)을 따른다.

복수 서버실 입력은 기존 입점 폼의 `colocation-grid`·`messenger-control`을 재사용해 밑줄 입력·회색 라벨·제목·간격·반응형을 통일한다. 개별 서버실 영역에 별도 카드 테두리·그림자·둥근 입력 박스나 폼 폭 변경을 적용하지 않는다. 추가/X와 입력 순서·검증은 유지한다. L2/L0 정적 diff·CSS 참조와 로컬 5301 화면의 기존/서버실 입력 높이·패딩·제목·테두리 표시를 확인했으며 테스트·빌드·실제 신청 제출은 미실행이다.

## 번역

### 2026-10-15 가입 약관 본문 번역 포함

사용자 첨부의 영문 가입 화면에서 약관 본문만 한국어로 남는 원인은 가입 화면의 Google 위젯 제외와 상위 `notranslate`, API 본문 수동 번역 제외였다. [가입 약관](src/routes/auth/-components/SignupTermsStep.tsx)에만 자동 번역을 허용하고 [본문](src/routes/auth/-components/SignupTermsCopy.tsx)은 안전한 `textContent`로 생성한다. API 본문 준비 후 위젯을 초기화하며, 제목·동의 문구·오류·버튼은 기존 수동 번역으로 유지한다. 본문 DOM은 Google에 맡겨 체크박스나 언어 표시의 React 갱신으로 번역된 문단이 교체되지 않게 한다.

동의 버전·내용은 기존 원문 계약을 유지한다. 번역 실행 중 다음 단계로 진행하면 동의를 저장하고 번역 쿠키를 지운 뒤 전체 문서 이동으로 회원정보 입력 화면을 연다. `/signup/terms` 및 `?mode=social`의 공개 약관 본문은 기존 Google 번역 서비스로 전달될 수 있다. 로그인·회원정보 입력·마이페이지·결제 화면은 기존 수동 번역 범위다. 아래 과거의 가입 약관 API 본문 제외 설명은 이 변경으로 대체한다.

L2/L0 정적 diff·경로·번역 차단 경계·본문 준비/관찰자 해제·동의 저장/이동·문서 참조와 독립 코드 리뷰를 확인했다. 테스트 파일·테스트·컴파일·빌드·lint·typecheck·실제 브라우저 번역·배포는 수행하지 않았다. [범위 기록](../docs/handoff/comviewers-translation-table.md#2026-10-15-가입-약관-본문-번역-포함)을 따른다.

### 2026-10-15 누락 화면 전체 수동 번역 연결

로그인·회원가입·장바구니 후속으로, 마이페이지 16개 경로와 같은 화면을 재사용하는 담당자 10개 경로·전용 로그인, 주문서/주문 결과, 게시글 작성/수정, 입점신청의 고정 UI 문구를 수동 번역에 연결했다. RCPC·즐겨찾기·주문/환불·보관함·포인트/쿠폰·문의/채팅·담당자/권한·프로필/로그인 보안과 각 팝업/검증/접근성 문구를 포함한다. 공통 에디터·후기 작성·세션/권한·오류/404·검색/날짜/선택 컨트롤도 연결했다. 공개 본문은 기존 Google 번역 경로를 유지한다.

`src/i18n/uiTranslation.ts`는 등록된 UI 원문을 정확히 조회하며 React 렌더링 단계에서 번역한다. 데이터 원본은 `mypage-rcpc-translations.ts`, `mypage-account-translations.ts`, `mypage-support-translations.ts`, `checkout-page-translations.ts`, `forms-page-translations.ts`, `common-page-translations.ts`, `catalog-ui-translations.ts`이며 기존 번역표와 합친다. 한국어 상태/정렬/문의 제목/환불 사유/영수증 enum은 원래 계약을 유지하고 표시만 번역한다. 원화 금액은 통화 환산 없이 각 언어의 KRW 표기로 출력하며 기존 한국어 강조 구조를 보존한다.

모바일 메뉴의 공개 화면 언어 선택은 이미 마운트된 Google 위젯의 선택 동작으로 전달해 본문 번역을 시작/변경하고 한국어 복원도 같은 경로를 따른다. 보호 경로에는 Google을 추가하지 않는다. 후기 작성 포털은 `notranslate`로 보호한다. 오류·동적 안내는 원문/값을 보관해 현재 언어로 표시하고 Toast는 이벤트 `toastKey`만으로 수명을 관리해 언어 변경으로 종료된 알림이 되살아나지 않도록 했다. 에디터 언어 변경은 안내·접근성 표시만 갱신한다.

이름·별명·서버실/그룹명·상품 정보·개인 입력·대화/후기/게시글 본문·약관 API 본문과 미등록 서버 오류는 원문을 유지한다. 관리자 앱·API/DB·결제 처리/계산은 이번 변경 범위가 아니다. [번역 범위와 검수 기록](../docs/handoff/comviewers-translation-table.md#2026-10-15-누락-화면-전체-수동-번역-연결)을 따른다. L2/L0 정적 diff·원문/키·5개 언어/placeholder·호출/import·AST 문맥·독립 리뷰 범위이며 테스트 파일·테스트·컴파일·빌드·lint·typecheck·실제 브라우저/결제·배포·원어민 검수는 미실행이다.

사용자 헤더의 장바구니 옆 `Language` 메뉴에서 한국어·영어·일본어·중국어 간체·번체를 선택할 수 있다. 공개 화면은 Google 웹사이트 번역 위젯을 사용하고, 로그인·결제·마이페이지 등에서는 수동 번역표를 사용한다. 관리자 앱은 대상이 아니다.

Google 위젯 허용 경로는 홈, 상품 목록·상세, 고객센터 목록·상세, 회사소개, 약관, 개인정보처리방침, 공개 게시글 목록·상세와 후기 목록이다. 게시글 작성·수정은 제외한다. 선택 언어는 같은 탭에서 유지되며 한국어를 선택하면 번역 쿠키를 지우고 원문으로 복귀한다.

수동 번역 데이터는 [translation-overrides.ts](src/i18n/translation-overrides.ts), 번역표의 검토 범위는 [번역 적용 기록](../docs/handoff/comviewers-translation-table.md)을 따른다. Google 위젯은 외부 서비스이므로 공개 화면의 내용이 번역 서비스에 전달될 수 있다.

### 2026-10-15 로그인·회원가입·장바구니 번역 누락 보완

Google 위젯을 사용하지 않는 경로에서 한국어 고정 문구가 수동 번역표에 연결되지 않아 헤더·금액만 번역되는 문제를 보완했다. 로그인, 회원가입·계정 복구의 화면 문구·입력 안내·등록된 검증/오류 메시지, 장바구니 제목·빈 상태·선택/삭제·주문 차단·비로그인 이관 안내와 공통 헤더/푸터를 선택 언어에 연결했다. 원본 데이터는 `src/i18n/auth-translations.ts`, `cart-page-translations.ts`, `shell-translations.ts`에서 관리하며 기존 표에 합친다. 한국어로 돌아갈 때도 같은 컴포넌트 상태에서 표시 문구가 갱신된다.

약관 API 본문, 사용자가 입력한 이름·아이디·이메일, 상품명·식별자, 등록되지 않은 서버 오류는 원문을 유지한다. 입력/인증/약관 동의·장바구니 계산과 Google 위젯 허용 경로는 기존 기준을 따른다. L2/L0 정적 diff·키/placeholder·import·호출·문서 참조 확인 범위이며 테스트 파일·테스트·컴파일·빌드·lint·typecheck·실제 브라우저 검수·배포와 원어민 검수는 수행하지 않았다.

## RCPC 교체 비용 결제

부품·디바이스 교체 비용은 담당자가 동일 금액으로 등록한 임시 상품을 고객이 기존 상품 구매·주문·결제 흐름으로 구매하여 수납한다. 고객의 교체 전용 견적·결제 화면은 제공하지 않는다. `교체 이용` 주문 필터는 교체가 완료된 새 장비를 뜻한다. 교체 처리와 검증 범위는 [전체 인수인계](../HANDOFF.md)를 따른다.

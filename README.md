# ComViewers 사용자 서비스 프론트

## 2026-09-10 PDF Description 반영

사용자·관리자 PDF를 함께 대조하며 live 화면과 API 계약을 보완하고 있다. 가입·이메일 인증/복구·프로필 이미지, 상품 필터/가격 분포, 실제 마이페이지 집계, C매니저 배정/개인 즐겨찾기, 문의 첨부/대상 추가, 게시판 clean 첨부/구조화 본문, 포인트·쿠폰 조건 검색, 할인 견적과 결제 이어가기, 다중 연장 주문서와 단계별 해지 신청을 연결했다. 고객 RCPC 상태·재부팅·WAN 조회는 현재 계약과 배정 권한으로 검증한다. 최신 범위와 잔여 조건은 [PDF 구현 기록](../docs/handoff/comviewers-pdf-description-implementation.md)과 [원문별 추적 목록](../docs/requirements/comviewers-pdf-description-inventory.md)을 따른다.

이번 변경은 L2/L3 정적 확인만 수행했다. 아래 과거 typecheck/lint/build 통과 기록은 이번 변경을 검증하지 않는다. 실제 메일·OAuth·PG·파일 저장/검사 설정과 신규 migration 적용 및 실행 검증은 별도다. 설정이 없는 공급자 응답을 성공으로 처리하지 않는다.

퍼블리싱 원본을 서비스 개발용 React 앱으로 전환한 사용자 프론트다. 원본은 `../comviewers-pub`, 이전 프리뷰는 `legacy-preview/`에 보존한다. `VITE_API_BASE_URL`을 지정하면 실제 인증·조직 capability·상품·장바구니·주문 견적과 마이페이지 조회 API를 사용하고, 지정하지 않으면 로컬 preview repository를 사용한다. live 마이페이지 홈은 프로필·RCPC·주문·혜택·문의·보관함·담당자·즐겨찾기 그룹 API를 합성하며, 내 정보 화면은 회원탈퇴 자격 조회와 요청을 연결한다. 주문서는 확정 약관 조회, 주문 생성, 결제 준비와 결제 상태 조회까지 연결하며 실제 PG 결제창·승인 callback은 provider 설정이 필요하다.

## 실행과 검증

Node.js 22.13 이상과 npm을 사용한다. 의존성 및 lockfile은 기존 승인 범위에서 설치했다. 이번 전체 화면 전환에서는 추가 설치하지 않았다.

```sh
npm ci
npm run dev
```

주소는 `http://127.0.0.1:5301/`이다. 관리자 앱은 `../comviewers-admin-www`에서 별도로 실행한다.

실 API 개발 모드는 `.env.local`에 다음 값을 둔다. 로컬 HTTP에서 refresh 쿠키를 확인하려면 API의 `COMVIEWERS_REFRESH_TOKEN_COOKIE_SECURE=false`도 필요하다.

```properties
VITE_API_BASE_URL=http://127.0.0.1:8080
```

```sh
npm run typecheck
npm run lint
npm run build
```

2026-09-08 사용자 명시 요청으로 위 세 명령을 실행하고 오류를 수정한 뒤 모두 exit 0을 확인했다. lint 오류·경고는 0건이다. 마이페이지 메뉴 타입, 미사용 코드, 훅 의존성과 모달 포커스 정리를 수정했다. 빌드에는 의존성의 use client/PURE 주석 경고와 약 774 kB JS 청크 경고가 남는다. lint는 TS/TSX 대상이다. 기능 테스트·브라우저 검증과 테스트 파일 추가/수정은 수행하지 않았다.

## 현재 전환 범위 — 2026-09-09

최신: 조직별 고객 capability와 프로필·포인트·쿠폰·주문·보관함·RCPC·문의 조회를 live 화면에 연결했다. C매니저는 RCPC·문의만 사용할 수 있고 public 화면은 조직 선택과 무관하게 열린다. 프로필 지원 필드 PATCH, RCPC 별명·즐겨찾기, 서버 그룹 ID 기반 그룹 생성·수정·삭제·RCPC 배정, 구매확정 렌탈별 상품후기 작성·수정·삭제를 실제 API에 연결했다. 후기 작성 후보가 없으면 차단하고 1건이면 자동 선택하며 여러 건이면 렌탈 선택 항목을 표시한다. 양 앱 typecheck/lint/build와 로컬 개발 계정 기반 HTTP·브라우저 통합 확인이 통과했다.

최신: 환경 변수 opt-in 방식으로 로그인·로그아웃·refresh 세션 복원과 활성 고객 조직 조회를 연결했다. 조직명과 대표 관리자/담당자 역할을 보존하며 담당자 조직은 장바구니·견적을 차단한다. 공개 상품, 대표 관리자 조직의 장바구니·서버 견적·상품후기와 주요 마이페이지 조회/저장은 HTTP repository를 사용한다. 게시판·입점·법무 repository는 아직 로컬이다.

후속: 상품 DTO→화면 adapter, API별 필터 지원 처리, 메모리 세션과 조직별 Query/서비스 격리, 장바구니·서버 견적 adapter를 추가했다. `app/createHttpCommerceServiceFactory.ts`가 명시적 연결 지점이다. 기본 실행은 mock이고 실제 로그인·HTTP 호출은 활성화하지 않았다. [연결 구조와 사용법](../docs/handoff/comviewers-frontend-service-transition.md#2026-09-08-상품-adapter세션장바구니-연결-구조)을 따른다. 아래 ‘Services 마운트 고정/adapter 별도 구현’ 설명은 이전 상태다.

최신: 두 앱 src의 JS/JSX를 모두 TS/TSX로 정리하고 allowJs/checkJs를 제거했다. src/api에 실제 백엔드 DTO 기반 HTTP 요청·응답 검증 모듈을 준비했다. 현재 화면은 mock을 사용하며 실제 API 호출은 활성화하지 않았다. 연결 방법과 계약 차이는 [전환 인수인계](../docs/handoff/comviewers-frontend-service-transition.md#2026-09-08-js-정리-및-api-연결-준비)를 따른다. 아래 단계별 전환 설명보다 이 상태를 우선한다. 이번 변경 후 두 앱 타입체크·lint·빌드를 재실행해 모두 통과했다. 기존 의존성·큰 청크 빌드 경고는 남으며 이번 HTTP 통합 테스트·브라우저 재검수는 하지 않았다.

일반 라우트의 실제 페이지 구현을 TSX로 전환하고 기존 JSX import는 호환 export로 유지했다. 후속 작업에서 `src/components`의 남은 실제 JSX 구현도 모두 TSX로 전환했다. 기존 `.jsx` 파일은 import 호환용 re-export다.

| 마이페이지 | 홈·RCPC·즐겨찾기·주문/상세·보관함·포인트·쿠폰·문의/상세·담당자·프로필을 typed 데이터·훅·화면으로 분리한다. |
| 공개 콘텐츠 | 홈·게시글 목록/상세/작성/수정·댓글·후기·고객센터를 Query와 ID 기반 조회로 연결한다. |

`app/ServiceProvider.tsx`에서 products/cart/checkout/myAccount/storefront 구현을 주입한다. 화면은 기능 훅을 통해 Query와 repository를 사용한다. 장바구니와 주문서는 같은 cart 인스턴스를 사용한다. 로컬 mock 변경은 새로고침하면 초기화된다.

상품 담기는 상품번호와 이용기간을 검증한 뒤 현재 상품을 재조회한다. 동일 상품은 선택 이용기간으로 갱신한다. 주문서에는 선택 ID 1~100개만 전달하고 객체·가격을 URL이나 location state에서 신뢰하지 않는다. 누락·중복·응답 불일치를 오류로 처리하고 장바구니 변경 시 견적을 무효화한다. 실제 재고 예약·가격 확정·주문 생성·결제는 수행하지 않는다.

## 남은 연결과 명확한 한계

- 실제 인증·권한·조직 경계·API·결제·첨부 업로드·원격 명령·감사기록은 미연결이다. UI의 로컬 검증은 서버 검증을 대체하지 않는다.
- 사용자 약관·개인정보처리방침은 live 모드에서 공개 발행본 카탈로그를 조회한다. 승인·발행된 본문이 없으면 임의 내용을 만들지 않고 빈 상태를 표시한다. 일부 고객센터 원본에도 본문이 없어 없음을 표시한다.
- 커뮤니티 저장은 메모리 mock이다. 리치 에디터 본문은 텍스트 문단으로 저장하며 서식·첨부 원문 업로드는 미연결이다. 사용자 요청으로 이런 개발 제약은 화면에 상시 표시하지 않는다.
- 장바구니 quantity는 기존 렌탈 기간 단위 또는 파트 수량이다. API quantity/durationUnits·billing unit·snapshot/current 가격·상품번호/항목 ID 매핑은 별도 구현해야 한다. RCPC방 시간 과금은 미구현이다.
- 비용·정산·구매확정·환불·연장·계정 변경 같은 동작은 실제 저장으로 연결하지 않는다. 기존 UI를 보존한 입력 초안과 미연결 안내를 제공한다.
- Services는 Provider 마운트 시 고정된다. 실제 로그인/조직 변경 시 캐시 폐기와 services 재생성을 구현해야 한다.
- `src/components` 구현은 TSX이며 props·이벤트·DOM ref를 타입화했다. 서비스 src는 strict TypeScript 검사 대상이며 원본·legacy-preview는 별도다. CSS·asset 보존은 시각 일치 검증과 다르다.
- `VITE_ENABLE_PUBLISHING_PREVIEWS=true`에서만 전용 시각 검수 경로와 완료 프리뷰를 연다. `/checkout/complete`는 일반 서비스에서 결과 미연결 안내를 표시한다.

이전 테스트는 `legacy-preview/src`에 보존했고 새 앱 검사에 포함하지 않는다. 현재 결과는 L2 정적 검토와 명시 요청된 타입체크·lint·빌드 통과다. 브라우저 동작·시각 검증 및 운영 배포 준비 완료를 의미하지 않는다.

[ADR 0024](../docs/decisions/0024-react-service-frontend-foundation.md), [전환 인수인계](../docs/handoff/comviewers-frontend-service-transition.md)를 따른다.

## 최신 후속 — 코드 분할·정책 점검·세션 UI (2026-09-08)

AppProviders의 authAdapter와 accessMode를 통해 로그인·로그아웃·조직 선택·보호 경로 UI를 연결했다. 기본 preview는 기존 화면 확인을 유지하고 enforced는 인증/권한/필요한 조직 선택을 검사한다. 실제 인증 adapter는 아직 주입하지 않았다. 관리자 초기 JS는 지연 로딩으로 약 1,049→427 kB로 줄었다. 환불 문구와 미구현 상품 등록/수정 경로 안내도 정리했다. 양앱 typecheck/lint/build 통과, 대표 화면 브라우저 확인을 수행했다. 사용자 큰 청크 및 의존성 빌드 경고는 남는다. 인증 세션 통합/전체 회귀/자동 기능 테스트는 미실행이다.

자세한 연결 계약·미완성 흐름은 [전환 인수인계](../docs/handoff/comviewers-frontend-service-transition.md#2026-09-08-코드-분할정책-점검세션-ui)를 따른다. 이 절이 위의 보호 경로·세션 UI 미구현 설명보다 최신이다.
## 최신 구조 정리 및 회귀 확인 (2026-09-08)

사용자 일반 페이지 지연 로딩(초기 JS 791→409 kB), 양앱 route-local 섹션/표/폼/모달/훅 분리를 완료했다. 관리자 초기 JS 427 kB이며 양앱 큰 청크 경고는 해소됐다. 홈 장바구니 이동·그룹 모달 초기화·주문 ID 선택·주문서 동적 높이도 보완했다. 양앱 typecheck/lint/build 통과, 대표 경로 390px 점검과 주요 로컬 동작/주문서1440px 확인을 수행했다. 자동 기능 테스트·실제 서버 통합은 미실행이다. 앞선 큰 청크 경고 설명보다 이 절이 최신이다.

상세 파일/검증 범위는 [전환 인수인계](../docs/handoff/comviewers-frontend-service-transition.md#2026-09-08-사용자-코드-분할양앱-화면-책임-분리회귀-점검)를 따른다.
## 최신 기능 보완 — 후기·문의·상품·렌탈 초안 (2026-09-08)

- 사용자 상품후기는 상품별 repository에 작성·수정·삭제·조회 갱신을 연결했다. 구매확정 렌탈별 1건, 본인 후기만 수정/삭제, 별점 1~5 및 본문 10~500자 검증을 적용했다. 기본 mock의 작성 가능 렌탈은 명시 합성 데이터이며 실제 구매/권한 판단은 서버 연동 때 대체해야 한다.
- 관리자 문의 /inquiries/:id는 실제 ID별 metadata/고객 대화 조회와 답변 초안 저장을 제공한다. 목록 링크·로딩·실패/재시도·없는 ID를 처리한다. 초안은 대화 발송이나 문의 처리완료로 반영하지 않는다.
- 관리자 상품 등록/수정은 등록된 PC 자산 선택·읽기 전용 수집 사양·상품명·메뉴·요금·설명 입력과 Zod 검증을 거쳐 mock 초안을 저장한다. 목록/수정으로 이어지며 새 초안의 마켓 노출은 차단된다. 실제 ComBar 자산 등록·상품 발행/영속 저장은 별도다.
- 관리자 렌탈 12개 액션 상태는 대상 선택·입력 폼·검증·확인 단계와 repository 초안/이력 조회로 연결했다(변경 이력은 조회 전용). 메모·즐겨찾기는 mock 표시에도 반영한다. 재부팅/종료/포맷/동기화·교체/연장 초안은 실제 원격 실행/결제/계약 변경이 아니다.
- 사용자 후기와 관리자 후기 데이터는 아직 별도 mock이다. 관리자 숨김과 사용자 노출 동기화, 실제 인증/권한·서버 영속/API·감사로그·동시성/실패 복구 통합은 남아 있다. 상품의 기타 fixture 계정/예약/필터/이력 팝업도 독립 잔여 범위이며 전체 기능 완성으로 판단하지 않는다.
- 검증: 주 작업자 보고 기준 양앱 typecheck/lint/build 통과. 사용자 후기 CRUD는 브라우저에서 확인했다. 관리자 문의·상품·렌탈의 확인한 경로는 아래 최종 브라우저 확인 범위를 따른다. 모든 팝업/오류/권한/화면크기 분기 검수나 자동 테스트 완료를 주장하지 않는다. 이 문서 갱신은 L0로 소스 경로와 관련 행 정합성만 확인했다.

상세 현재 범위는 [전수 점검](../docs/handoff/comviewers-screen-audit.md) 및 [전환 인수인계](../docs/handoff/comviewers-frontend-service-transition.md)를 따른다. 이전 미저장/ID 미사용/상품 폼 부재/렌탈 안내-only 설명은 이 절의 대상에 한해 과거 상태다.

- 관리자 상태 변경 브라우저 검수는 자동 승인 review가 차단했다. 로컬 메모리 초안만 변경한다는 소스 근거를 제시했으나 관리자 read-only 규칙 위반이라는 사유로 저장 클릭을 거절했다. 따라서 이번 추가 관리자 초안 저장 검수는 미실행이며 사용자 허용을 요청할 예정이다. 이는 기능 실패 판정이나 이미 수행한 이전 단계 검수의 취소가 아니다.
- 실제 API·영속 저장·계정/권한·승인/정산/배포·전체 화면 시각 및 분기 검수는 완료되지 않았다. 이 검증 기록 추가는 L0 문서 수정이다.

## 최신 API 연결 마감 — 2026-09-09

- `/api/auth/signup/terms`, 이메일 인증 요청·확인, `/api/auth/register`를 가입 2단계 화면에 연결했다. 동의한 정책 버전 ID를 세션 탭 범위에 보존하고 이메일이 바뀌면 기존 인증 proof를 폐기한다.
- 아이디 찾기, 비밀번호 재설정 메일 요청, 메일 링크의 토큰 기반 새 비밀번호 저장 화면을 실제 복구 API에 연결했다. 계정 존재 여부를 노출하지 않는 서버 응답에 맞춰 완료 문구를 구성했다.
- 현재 로컬 DB는 가입 필수 약관 전체가 발행되지 않아 가입 약관 조회가 차단된다. 프론트는 이를 오류·재시도로 표시하며 임의 약관이나 성공 상태로 대체하지 않는다.
- 일반 법무 화면은 종류별 공개 카탈로그 API를 사용해 발행·발효된 서비스 이용약관·렌탈약관·개인정보처리방침만 조회한다. 승인된 본문을 새로 만들거나 mock으로 대체하지 않으므로 DB에 발행본이 없으면 빈 상태를 표시한다.
- 마이페이지 RCPC 목록은 기존 `/api/v1/my/rcpcs/summary`를 함께 조회해 전체 및 상태 선택지에 조직 권한 범위의 실제 건수를 표시한다. 즐겨찾기 화면은 전체 조직 집계를 섞지 않고 현재 필터 결과 건수만 유지한다.
- 앞선 절의 인증·커뮤니티·문의·C매니저·RCPC 그룹·후기 미연결 설명은 최신 구현 범위에는 해당하지 않는다. 실제 주문 생성·결제·환불·정산·원격 자격정보와 입점 첨부 업로드는 여전히 별도 계약 또는 L3 작업이다.
- 검증: `npm run typecheck`, `npm run lint`, `npm run build` 통과. 비밀번호 재설정 경로 렌더링과 가입 약관 API 오류 상태를 로컬 브라우저에서 확인했다. 테스트 파일은 추가하지 않았다.

## 가능한 계약 연결 및 보류 항목 — 2026-09-09

- 보관함의 `stored` 상품을 기존 `POST /api/v1/my/storage/{itemId}/move-to-cart`에 연결했다. 렌탈 상품은 서버가 내려주는 최소·최대 이용기간 안에서 기간을 선택하고, 일회성 상품은 기간 없이 요청한다. 실행 전 확인 단계와 중복 요청 방지 키를 사용하며 성공하면 보관함과 장바구니 Query를 함께 갱신한다.
- 보관함 API 응답에 기존 상품 데이터의 `minUnits`·`maxUnits`를 노출했다. 로컬 H2에서 조회를 막던 `users user` 예약어 별칭도 `users account`로 수정했다.
- 로컬 개발 계정으로 로그인·조직 선택·보관함 빈 상태를 실제 API로 확인했다. 검증 조직에 보관 상품이 없어 이동 요청은 실행하지 않았고, 브라우저 console warning/error는 없었다.
- 소셜 로그인 버튼을 기존 Google·Naver·Kakao authorization endpoint에 연결했다. API callback은 token 없는 `result`만 사용자 웹 `/auth/social/callback`에 전달하고, 기존 회원은 HttpOnly refresh cookie로 세션을 복원한다. 신규 회원은 HttpOnly 가입 cookie로 공급자·검증 이메일 컨텍스트를 조회한 뒤 기존 약관과 소셜 전용 추가정보 화면에서 가입한다. 실제 provider client 설정·redirect URI 등록과 외부 callback 검증은 남았다. 입점 신청은 첨부의 `storageKey`·SHA-256을 발급하는 업로드 계약과 동의할 정책 버전 공급원이 없어 제출을 연결하지 않았다.
- 소셜 callback 변경은 인증·쿠키 L3다. URL token 비노출, 고정 redirect, HttpOnly cookie 경로·만료, 기존 JSON 호환과 프론트 route 연결을 정적으로 확인했다. 검토 과정에서 사용자 앱 `npm run typecheck`와 API `gradlew compileJava`는 통과했으며 lint·build·전체 테스트·외부 OAuth 실행은 수행하지 않았다.
- 그 밖의 보류 항목과 필요한 계약은 [전환 인수인계](../docs/handoff/comviewers-frontend-service-transition.md#2026-09-09-가능한-계약-연결과-보류-기록)를 따른다.
